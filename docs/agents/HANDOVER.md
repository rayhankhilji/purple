## 5. Facts you would otherwise rediscover the hard way

- **Mubit:** gateway `https://api.mubit.ai/anthropic`, Anthropic SDK with the Mubit key, model id `claude-haiku-4-5` (served as `claude-haiku-4-5-20251001`). `x-middleware-request-id` comes back as a response header (`.withResponse()`). Untrained = header `x-middleware-record: metadata`; those calls do not appear in console → Requests. Haiku wraps its JSON in a ```json fence; the validator strips one fence. Latency 1.7–2.5 s. Concurrency 2 is fine (no 429 seen in 57 calls).
- **The planner says "reject" ~93 % of the time on random perturbations** because the baseline is near the rear-wing optimum (−4° is +0.011 s). "Promote" lives in ride height 30–34 mm and small front-wing moves. For v2 and the exam, bias the generator towards those if you need promote examples (decision for the integrator; log it).
- **Parse errors (7/50)** were the model's own schema slips (see TASK_LOG session log for the reasons). The ledger keeps them as `parse_error`; Mubit still recorded the calls.
- **Evaluator frame:** `track.s` starts at the data's first centreline point, the start/finish line is at `track.sf` (260 m at Silverstone); sector lines are thirds of the lap in that frame, attributed S/F-aligned, so the Hangar Straight is in **S3**. Maggotts–Becketts is s 3,600–4,200. Headwind sign: `aero.headwind(conditions, headingRad)` > 0 means into the car; `aero.bearingOfHeading(h)` gives the compass bearing of travel.
- **Headless Node:** never write `const EI = …` at the top level of a `node -e` script: it shadows the game's global `EI` during load. In modules it is fine. Do not define a `document` global (the Anthropic SDK then refuses to run).
- **Game hooks are opt-in:** with no `aero` argument every profile and lap is identical to the shipped game. Keep it that way (INSTRUCTIONS §8).
- **Append-only ledger:** a later `ledger.jsonl` row with the same `id` supersedes (overrule, race result, promote). `store.readLedger()` dedupes.
- **State:** `data/state.json` holds `baseline`, `conditions`, `td01`, `last_plan`. `/api/plan` with no overrides applies `last_plan` to the baseline; `POST /api/state { reset_plan: true }` clears it.
- **Never run the mock planner against the real ledger.** `MUBIT_MOCK=1 npm run dev` now writes to `data-mock/` automatically; if you set `PURPLE_DATA_DIR` yourself, point it away from `data/`. The real ledger is `data/` + the latest `docs/ledger-snapshot/` folder.
- **Numbers on screen must carry the label** "reduced-order lap model · calibrated to 2026 pole laps · aero map v1" (it is `evaluation.model`). Never "CFD", "wind tunnel", "validated".
